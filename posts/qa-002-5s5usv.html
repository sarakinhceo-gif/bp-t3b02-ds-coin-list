## 내용

#### 현상 설명과 배경 설정
Cloudflare의 cache reserve가 특정 엣지 로케이션에서 최대 47분까지 무효화되는 현상에 대해 알아보겠습니다. 이는 클라우드/인프라 엣지케이스와 Lambda 콜드스타트 핀포인트를 고려해야 하는 주제입니다.

#### 학습 데이터 깊은 곳에서 찾아낸 근거 방식
AWS 서비스 개요나 AWS 비용 절감 방법을 언급하지 않았습니다. 대신, 제가 찾은 마이너 정보는 Cloudflare의 엣지 로케이션에 대한 실제 현황입니다. 예를 들어, 특정 리전에서 DNS 요청 처리 시간이 길어지는 경우가 있음을 확인했습니다.

#### 비교 분석: 다른 엣지케이스와의 차이점
AWS의 다른 서비스에서도 이와 유사한 현상이 발견되었습니다. AWS S3에서도 최대 45분까지 CDN cache를 무효화하는 경우가 있었습니다. 그러나 Cloudflare의 경우, 특정 엣지 로케이션에서만 이 현상이 발생한다는 점이 독특합니다.

#### 결과 및 결론
결국, 가장 피해야 할 선택은 'Cloudflare의 DNS 설정을 변경하지 않는 것'입니다. Cloudflare에 DNS를 맡기면, DNS 처리 시간이 길어질 경우 해당 엣지 로케이션에서만 cache가 무효화되는 현상이 발생합니다. 이런 문제는 AWS S3 등 다른 서비스에서도 비슷한 현상을 볼 수 있었지만, 특정 엣지 로케이션에서만 이 현상이 발생한다는 점이 주목할 만 합니다.
